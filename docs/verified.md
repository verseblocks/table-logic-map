## Additional facts verified against PPTB 1.2.5

- `package.json#features` **requires** `multiConnection` whenever `features` is present (`@pptb/validate`): use `{ "multiConnection": "none", "minAPI": "1.2.5" }`.
- `configurations.readmeUrl` must not be on `github.com` (use `raw.githubusercontent.com`); `repository`, `website` and `readmeUrl` are HEAD-checked for reachability unless `skipUrlChecks` is used. The published CLI has **no** `--skip-url-checks` flag; `npm run validate:offline` calls the library with the flag instead.
- `icon` is relative to `dist/`; Vite copies `public/` into `dist/`, hence `public/icons/table-logic-map.svg` → `"icon": "icons/table-logic-map.svg"`.
- `pptb.config.json` must be listed in `files` or MCP discovery never sees it.
- Windowed MCP launches inject `__pptb = { source: 'mcp', mode, correlationId, timeoutMs, expectsResponse }` into `getLaunchContext()`; two-way windowed results are validated against `returnTopic` and the window is closed after `returnData`.
- MCP friendly tool name = `displayName` lower-cased with non-alphanumerics replaced by `-` → `table-logic-map`.
- `sdkmessageprocessingstep.ishidden` (like `iscustomizable`) is returned by the Web API as a `BooleanManagedProperty` object `{ Value, CanBeChanged, ManagedPropertyLogicalName }`, not a plain boolean; sources read it with `boolValue()` (which also accepts a plain boolean).
- The `capabilities` tag `table-logic-map` is not in the built-in registry; `pptb-validate` emits a warning (not an error). Request the tag from the PPTB team to make discovery via `findToolsByCapability` official.
